# 自定义与当前边界清单

更新：2026-11-06。以下按实际代码填写。

**本文中的“可自定义”就是“用户可以通过脚本实现”。软件负责生成脚本、传入选择项、绑定菜单并管理执行。复杂业务流程本身不会因为没有专用配置字段而被判定为不支持。**

## 一、已经迁移的现有功能

- [x] 在终端中打开：`terminal.zsh`。
- [x] 复制路径：`copy-paths.zsh`。
- [x] 固定到程序坞：`pin-dock.zsh`。
- [x] 移动到指定目录：`move.zsh`，每个目标目录对应一份动作绑定。
- [x] 拷贝到任意目录：`copy-to.zsh`，一次选择目录后拷贝全部选中项；可自定义目标、命名和冲突策略。
- [x] 发送到 LocalSend：`localsend.zsh`。
- [x] 桌面快捷方式：`symlink.zsh`，实际创建符号链接。
- [x] 旧版目标目录自动备份并迁移，动作 ID 在迁移后保持稳定。
- [x] 动态生成 Finder 菜单，支持文件、目录、混合多选和空白处上下文。
- [x] 默认菜单包含常驻的“打开方式”分组；未添加应用时显示禁用占位项。
- [x] Finder 动作在后台唤醒主程序，不自动弹设置窗口或抢焦点；失败通过菜单栏状态和执行结果呈现。

终端与 Dock 只适用于目录，其他文件动作默认允许文件与目录。条件不符时不显示，依赖缺失时禁用。

## 二、可自定义：软件已提供的生成和编辑入口

| 用户操作 | 软件替用户做什么 | 用户还能修改什么 |
| --- | --- | --- |
| 添加打开方式 | 从选择的应用生成独立 zsh 脚本、动作、菜单引用 | 应用参数、执行前后处理、适用文件类型 |
| 添加移动目标目录 | 生成调用移动脚本的动作和菜单项 | 目标、命名、冲突、重试等脚本策略 |
| 添加固定拷贝目标 | 生成调用拷贝脚本的动作和菜单项，保留“每次选择”动作 | 目标、命名、冲突、重试等脚本策略 |
| 管理发送到动作 | 启用/停用组内动作，添加已有动作引用或移除引用 | 发送动作组合和菜单顺序 |
| 添加自定义脚本 | 保存脚本正文、检查语法、生成动作及“自定义”分组 | 完整脚本逻辑 |
| 打开脚本目录 | 展示可编辑的用户副本 | 所有默认模板和自定义脚本 |
| 编辑配置 | 打开实际生效的 JSON | 名称、分组、条件、脚本路径和执行参数 |
| 菜单栏查看结果 | 汇总退出状态和输出 | 脚本自己输出的日志和业务说明 |

默认脚本只在缺失时从应用模板复制，保留用户已有修改。直接编辑脚本后，下一次点击使用修改后的内容。编辑 JSON 后主程序约 3 秒内重新加载，菜单重新打开时使用新配置。

## 三、可自定义：脚本能够实现的操作

下列都属于当前框架可以承载的用户自定义能力。前提是相应工具已安装、当前用户具备操作所需的系统权限，并满足运行时限制。

| 操作类型 | 脚本实现思路 |
| --- | --- |
| 用任意应用打开 | `open -a`、`open -b` 或应用自己的 CLI |
| 文件复制、移动、删除和重命名 | 系统命令与用户自己的命名、冲突和重试策略 |
| 新建文件、目录、模板文件 | `mkdir`、`touch`、`cp`、`printf` 等 |
| 压缩、解压与归档 | 系统或用户安装的归档工具 |
| 文本、图片、音视频格式转换 | 已安装的转换程序或解释器 |
| 校验和、文件信息与分析报告 | `shasum`、`stat`、文本处理工具等 |
| Git 或其他开发工具操作 | 已安装 CLI 的参数组合 |
| 网络上传、下载和 API 调用 | 脚本自己的网络命令、认证配置和错误处理 |
| 多步骤流程 | shell 函数、顺序命令、管道、条件和循环 |
| AppleScript、JXA、Python、Node 等 | 调用系统支持或用户已经安装的解释器 |
| 外部应用自动化 | 调用该应用提供的 CLI、脚本接口或自动化能力 |

多步骤、管道、条件和循环写在脚本里，因此它们不是当前框架“不适用”的业务类型。框架没有必要给每条命令、每种格式或每个应用增加原生组件。

## 四、可调整的动作绑定配置

| 配置 | 支持内容 |
| --- | --- |
| 菜单 | 名称、图标、顺序、分组、分隔符、一个动作的多个引用 |
| 显示条件 | 文件/目录类型、扩展名、目标数量、右键入口 |
| 启用状态 | enabled 开关 |
| 解释器和脚本 | 可执行文件绝对路径、脚本文件路径、参数数组 |
| 目标参数 | 全部目标或逐项执行，路径、文件名、父目录、当前目录、用户目录 |
| 执行方式 | all/each、each 出错停止或继续 |
| 运行环境 | 工作目录、环境变量、标准输入 |
| 结果约定 | 超时 1–600 秒、自定义成功退出码 |
| 依赖 | 应用名称、bundle ID、应用路径、依赖文件路径 |

完整字段与默认值见 [配置契约](configuration.md)。设置界面覆盖常见脚本生成操作；高级字段当前通过 JSON 编辑，不是每个字段都有专门表单。

## 五、不适用于当前框架的配置或运行假设

| 不适用项 | 当前原因与边界 |
| --- | --- |
| 直接用一个字符串表示整条命令 | `arguments` 必须是数组；将管道等逻辑写进脚本 |
| 在 JSON 中加入任意未声明字段 | 严格校验会拒绝；逻辑写进脚本，绑定使用已支持字段 |
| 将 `{paths}` 嵌入一个普通参数 | 它是列表，只能作为完整数组元素；用脚本将参数按需要重新组织 |
| all 多选却使用单目标变量 | 使用 `{paths}`，或改成 each/maxCount=1 |
| 菜单生成时运行脚本决定菜单结构 | 当前菜单树与匹配条件是声明式的；脚本在点击后才执行 |
| 把脚本输出直接变成新的 Finder 原生子菜单或表单 | 尚无这种输出协议；需要单独实现界面适配器 |
| 不选择目标的全局菜单动作 | 当前上下文模型要求至少一个目标；空白处对应当前目录 |
| 执行时交互式终端输入、密码提示或 TTY | 使用普通管道，没有终端会话；脚本可自行打开 Terminal，但新终端不受原任务生命周期管理 |
| 由框架管理常驻后台进程、守护程序或定时任务 | 单次任务最长 600 秒，结束/取消会清理受管子进程；没有服务管理和调度模型 |
| 自动回滚任意多步骤脚本 | 框架不知道业务副作用；补偿和回滚由脚本实现 |
| 脚本自动得到管理员或隐私权限 | 脚本继承运行用户与系统权限，不自动绕过限制 |
| 自动安装所有脚本依赖 | 当前只检查声明的依赖，不附带解释器或安装器 |
| 接受 URL 中传来的命令或脚本文本 | URL 只定位本地请求文件；执行内容必须来自本机配置和脚本 |
| 宣称本地请求文件能认证发送程序身份 | 当前只有同用户本地文件边界，正式签名 IPC 尚未实现 |
| Windows/Linux 直接使用 Finder 入口 | 入口适配器为 macOS FinderSync，需要另写平台适配器 |
| 所有 macOS 目录都保证显示扩展菜单 | 仍受 Finder Sync 的实际覆盖范围影响 |

其中“尚无 UI 协议”“尚无服务管理”等是框架能力边界；不能因此把普通文件处理或脚本业务逻辑列为不支持。

## 六、会被直接拒绝的配置例子

错误：参数不是数组。

```json
{ "type": "command", "executable": "/bin/zsh", "arguments": "my-script.zsh {paths}" }
```

正确：脚本路径和目标列表分别传入。

```json
{ "type": "command", "executable": "/bin/zsh", "arguments": ["{home}/my-script.zsh", "{paths}"] }
```

错误：把目标列表拼进一个参数。

```json
{ "type": "command", "executable": "/usr/bin/tool", "arguments": ["--files={paths}"] }
```

正确：传入独立参数，由工具或脚本处理。

```json
{ "type": "command", "executable": "/usr/bin/tool", "arguments": ["--files", "{paths}"] }
```

后一例中的 `/usr/bin/tool` 只是占位路径，使用时必须替换为实际工具。

旧设计稿中的 `files.move/files.symlink/dock.pin` 原生 builtin 定义不再适用：这些文件操作已经落实为可编辑脚本。保留的 builtin 只有打开设置和添加目标目录等软件自身的界面入口。

## 七、文件位置与使用步骤

用户数据根目录：

```text
~/Library/Containers/com.finderx.app.finder/Data/Library/Application Support/FinderX/
  config.json                   菜单与动作绑定
  config.last-good.json         最近有效配置
  config.json.legacy-backup     旧版目标目录备份（发生迁移时存在）
  config.before-copy-to.json    拷贝到动作迁移前配置备份（发生迁移时存在）
  config.copy-to-migrated       拷贝到动作迁移标记
  config.open-with-migrated     打开方式分组迁移标记
  Scripts/                     用户实际运行和编辑的脚本
  availability.json            应用与脚本依赖状态
  Requests/                    等待主程序消费的临时请求
  last-execution.json           最近一次完整执行结果
```

操作步骤：

1. 构建、安装并启用 Finder 扩展。
2. 在设置里选择应用、添加目录或编写自定义脚本。
3. 在 Finder 重新打开右键菜单执行。
4. 有问题时从菜单栏查看“最近执行结果”，或检查脚本和 JSON。

脚本模板源码位于项目的 `Resources/Scripts/`；编辑这里影响未来安装的初始模板。要改变当前用户实际执行行为，请编辑用户目录下的副本。
