# FinderX 脚本动作框架

状态：现有功能已按本框架实现。更新：2026-11-06。

## 1. 产品定义

**FinderX 把用户的选择和偏好生成脚本，再把脚本绑定到 Finder 右键菜单。用户自定义，就是用户可以编写、修改或替换脚本。**

JSON 负责菜单、适用条件、脚本路径和运行参数；操作细节放在脚本里。复制、压缩、转换、批量重命名、调用其他程序和多步骤处理，都属于脚本可以表达的用户自定义操作，不需要为每种功能新增 Swift 分支。

基础链路：

```text
选择应用 / 添加目标目录 / 编写自定义操作
    → 生成脚本与菜单配置
    → Finder 获取上下文
    → 匹配并展示菜单
    → 生成确定的执行计划
    → 主程序运行脚本
    → 返回退出码、输出和执行结果
```

例如添加 Sublime Text，软件生成独立脚本：

```sh
#!/bin/zsh
set -euo pipefail
/usr/bin/open -a '/Applications/Sublime Text.app' "$@"
```

用户可以直接修改这个脚本。选择路径始终作为独立参数传入，脚本用 `"$@"` 读取。

## 2. 核心抽象与目录

| 概念 | 职责 | 实现 |
| --- | --- | --- |
| ActionContext | 入口、原始选择、当前目录、本次目标的不可变快照 | `Sources/Core/Models.swift` |
| ActionDefinition | 名称、条件、批量方式和执行定义 | `Sources/Core/Models.swift` |
| MenuDefinition / MenuModel | 菜单树与动作引用；展示与行为独立 | `Sources/Core/Matching.swift` |
| ExecutionPlan | 已展开的程序、参数、环境、输入和任务 | `Sources/Core/Planning.swift` |
| ExecutionResult | 状态、退出码、输出、错误和时间 | `Sources/Core/Models.swift` |

```text
Sources/Core/                 数据模型、配置校验、条件匹配、菜单模型、计划生成
Sources/Runtime/              串行调度、进程输入输出、超时与取消、界面操作注册表
Sources/Platform/macOS/       应用查找、脚本生成与安装、文件移动 CLI 原语
Sources/Shared/              容器路径、请求文件传输、依赖可用性快照
Sources/FinderExtension/     Finder 上下文采集和 NSMenu 渲染
Sources/App/                 菜单栏、配置管理、脚本编辑、结果展示
Resources/Scripts/           首次运行复制给用户的脚本模板
Tests/                       框架与脚本回归测试
```

Core 使用系统 Foundation、CryptoKit 和自有类型；不依赖 AppKit 或 FinderSync。运行时、Finder 和界面通过这些类型协作。当前继续使用 `swiftc` 构建，没有引入第三方组件或独立插件运行时。

## 3. 现有功能如何落地

| 功能 | 脚本模板 | 输入 | 行为 |
| --- | --- | --- | --- |
| 在终端中打开 | `terminal.zsh` | 全部目录 | `open -b com.apple.Terminal` |
| 复制路径 | `copy-paths.zsh` | 全部目标 | 字面输出路径，通过管道交给 `pbcopy` |
| 固定到程序坞 | `pin-dock.zsh` | 全部目录 | 写入 Dock 偏好，去重后最多重启一次 Dock |
| 移动到 | `move.zsh` | 目标目录、一个源对象 | 重名加后缀，防止移动进自身，逐项执行 |
| 发送到 LocalSend | `localsend.zsh` | 全部目标 | `open -b org.localsend.localsendApp` |
| 桌面快捷方式 | `symlink.zsh` | 桌面目录、一个源对象 | 创建符号链接，重名加后缀，逐项执行 |
| 新增打开方式 | 每个应用独立生成 `.zsh` | 全部目标 | `open -a` 指定所选应用 |
| 自定义操作 | 用户编写的独立 `.zsh` | 全部目标 | 用户自己的脚本 |

除终端和 Dock 只接收目录外，其余文件操作默认支持文件与文件夹。LocalSend 不存在时菜单项禁用，并保留缺少依赖的原因。

默认菜单包含常驻的“打开方式”分组；尚未添加应用时显示禁用占位项，添加应用后在同一分组内追加。

`builtin` 仅用于“添加目标文件夹”“打开设置”等需要主程序界面的管理操作，不能配置任意 Swift 函数名。现有六类文件操作都经过脚本执行链路。

### 一个必要的底层 CLI 原语

macOS 的 `mv` 没有 GNU `--no-target-directory` 选项。单纯“检查目标不存在，然后 mv”存在竞争窗口，目标若被并发创建为目录，源对象可能被移入该目录。

因此软件提供内部命令：

```sh
"$FINDERX_EXECUTABLE" --move-no-replace "$source" "$candidate"
```

它使用系统 `renamex_np(..., RENAME_EXCL)` 完成独占重命名。目标已存在返回 17，脚本决定是否尝试下一个名字。跨卷时先复制到目标卷的临时位置，再独占发布并删除源对象；删除源对象失败会明确报告已复制但未完成删除。

这是脚本调用的命令行工具，命名策略、循环、条件判断和实际工作流程仍在可编辑脚本里。默认移动与符号链接模板使用它，其他用户脚本可自行选择普通系统命令。

脚本退出码约定：`0` 成功，`100` 已跳过，`130` 已取消，其他非零值失败。默认 `copy-to.zsh` 在用户取消目标选择时返回 130，`move.zsh` 在源已位于目标目录时返回 100。脚本模板只在首次安装时复制；内置 `copy-to`/`move` 会通过一次性迁移更新旧默认行的退出码，其他用户修改不会被覆盖。

## 4. 上下文与菜单语义

- `items/sidebar`：使用本次选择项，按路径去重且保留顺序。
- `container`：使用右键所在目录，不采用 Finder 残留的选择项。
- 不静默过滤混合多选。例如文件加目录的选择不适用于终端动作，整个动作不显示。
- 每个菜单项绑定独立上下文快照，点击时不读取另一次右键的选择。
- 快照保存在扩展内的 MenuBindings，通过 NSMenuItem.tag 关联；不能依赖自定义 representedObject 穿过 Finder 的跨进程菜单回调。
- 保留选中的路径，不默认替换成符号链接的目标路径。
- 条件全部满足才展示动作；空分组和首尾、重复分隔符被清理（`showWhenEmpty` 分组除外）。
- 菜单展示只读取配置与依赖快照，不启动进程或探测网络。

菜单节点为 `group/action/separator`，动作通过稳定 ID 引用。同一个脚本动作可以被多个菜单节点复用。

## 5. 脚本生成、保存和修改

首次启动将 `Resources/Scripts/` 复制到用户扩展容器的 `Scripts/`。同名文件已经存在时保留原文件，后续构建和安装不会覆盖用户修改。

设置窗口提供：

1. **添加打开方式**：选择 `.app`，生成独立打开脚本和菜单引用。
2. **添加自定义脚本**：填写名称和 zsh 正文，检查语法后保存；保存过程不执行脚本。
3. **打开脚本目录**：用用户自己的编辑器修改任何脚本。
4. **编辑配置**：修改菜单、条件、解释器、参数、环境和超时。
5. **移动目标列表**：增加、移除移动动作，复用同一个移动脚本。

应用路径写进脚本时经过 shell 字面量转义；选择项通过参数数组传入。脚本中的管道、循环和重定向由用户选择的解释器解析。

默认生成器使用 `/bin/zsh`。用户可以在 JSON 中把命令改成其他已安装解释器与脚本路径；软件不附带这些解释器。

脚本正文不属于 JSON revision：编辑脚本后，下一次执行使用当前文件内容。revision 用于保护 JSON 中的动作绑定与执行参数，避免旧菜单执行同 ID 的新配置。

## 6. 执行机制

`PlanBuilder` 将动作与上下文展开成独立任务。变量是一次替换，不递归解释文件名中的 `{...}`，也不隐式展开 `~`、通配符或 `$()`。

- `all`：一次脚本获得全部目标。
- `each`：每个目标独立启动一次脚本，保持选择顺序。
- 调用与任务均串行执行，默认遇错停止；`each` 可设置出错继续。
- 默认工作目录为用户主目录，默认超时 30 秒，可配置为 1–600 秒。
- 标准输入、标准输出与标准错误采用非阻塞管道一起处理；两个输出流各保留最多 64 KiB，超出后继续排空。
- 超时、取消通过受管进程组终止脚本与子进程；常驻后台任务不是本执行器的生命周期模型。
- 成功、失败、部分完成、取消和超时以结构化结果返回，最近结果可从菜单栏查看。
- Finder 动作在后台唤醒主程序。启动、reopen 和扩展状态检查都不会自动弹设置；成功静默，失败仅更新菜单栏图标和结果，设置与详情由用户主动打开。

外部脚本退出 0 视为成功，其他退出码默认失败；可通过 `successExitCodes` 改变成功码约定。默认脚本的“已经在目标目录”等无操作情形退出 0，并在标准输出说明跳过。框架不通过解析脚本文字猜测逐文件状态。

`open` 成功退出表示已提交打开请求；不代表外部应用已经完成编辑或发送。多步骤脚本内部的部分修改、回滚和重试由脚本负责；框架保留已经完成的任务，不自动撤销文件修改。

## 7. 配置仓库与旧数据迁移

配置版本为 `schemaVersion: 1`。校验包括未知字段、枚举、重复 ID、悬空引用、菜单深度、数量条件、变量类型和执行定义。

配置原子写入；有效内容生成 SHA-256 revision；主程序每 3 秒检查配置与依赖，扩展每次构建菜单读取配置。保存时同时维护 `config.last-good.json`。

配置损坏时继续使用最后可用快照并报告错误，不覆盖损坏文件。旧版 `{ "destinations": [...] }` 会备份为 `config.json.legacy-backup`，随后转换成完整脚本动作与菜单。迁移后的移动动作使用 UUID，重启不会再次创建或改变 ID。

当前脚本、配置位置和可定制范围见 [自定义与边界清单](customization-checklist.md)。

## 8. 本地构建的跨进程传输

当前本地签名版本使用扩展容器内的请求文件，不依赖 Team ID 或新 XPC 服务：

```text
Finder 扩展
    → 写入私有临时请求文件
    → 独占、原子发布 UUID.json
    → 打开 finderx://invoke?request=UUID
主程序
    → 根据 UUID 从固定请求目录读取
    → 检查文件所有者、类型、权限、大小和时效
    → 消费文件，拒绝重放
    → 根据自身配置校验动作与 revision
    → 重新检查目标与依赖
    → 生成计划并执行
```

URL 只携带随机请求 ID，不能携带命令、脚本文本或任意请求文件路径。请求超过 60 秒不执行。旧版通过 URL 直接携带路径的 pin、shortcut、move 路由已停用；更新时需要同时安装新版 Finder 扩展。settings、add-destination 仍作为纯界面入口保留。

这种传输是同用户本地信任边界，不能认证发送进程的代码签名；具备同用户文件写权限的程序仍属于该边界内。正式签名分发时，可以替换 `InvocationTransport` 为经过身份验证的 IPC，并替换共享存储为 App Group，核心动作模型不变。

## 9. 复用方式

新增用户功能：写脚本 → 添加动作定义 → 添加菜单引用。不修改 Finder 渲染器、匹配器或执行器。

新增预设表单：把表单参数转义后写入脚本，再生成同样的动作定义。不为每个预设增加新的执行类型。

新增入口：构造 `ActionContext` 和 `Invocation`，交给同一个 `ActionDispatcher`。核心无需知道入口是不是 Finder。

新增平台集成：只有脚本无法表达入口或界面交互时才增加适配器。例如新的 Finder 上下文来源或主程序表单，而不是把文件处理流程重新写成原生功能分支。

## 10. 验证范围

运行 `scripts/test.sh` 验证配置迁移与恢复、变量、条件和菜单、请求消费与去重、字面参数、大输出、输入关闭、进程超时与取消、移动冲突、符号链接、用户脚本保留、语法校验和部分失败。

测试使用临时目录；不实际写入 Dock，也不启动 Terminal、第三方编辑器或 LocalSend。Dock 的 URL 与 XML 编码通过只运行纯编码函数验证。

Finder 实际菜单覆盖范围、目标系统的扩展启用、第三方应用行为和隐私权限仍需要本机交互验收。当前版本继续采用本地 ad-hoc 签名构建。

0.2.1 已完成当前开发机普通本地目录的真实菜单操作验收，详见 [验证记录](verification-2026-11-06.md)；脚本测试与实际跨进程菜单测试分别记录。
