# 0.2.1 真实 Finder 验证记录

这是改名前 SuperRight 0.2.1 的历史验证记录；项目现名 FinderX，本文保留当时实际使用的名称与版本。

日期：2026-11-06。环境：当前开发机上已安装的 `~/Applications/SuperRight.app`，扩展注册版本 0.2.1。

## 本次故障与修复

0.2.0 的框架和脚本单元测试通过，但 Finder 点击到主程序之间的真实链路没有验收。实际表现是所有菜单点击没有结果：`last-execution.json` 不存在，扩展也没有发布请求。

根因在 Finder 适配器：菜单项将自定义 `MenuInvocation` 实例放在 `representedObject`；Finder 跨进程返回的是重建后的菜单项，该实例没有随回调保留。`guard let binding = ...` 因此直接返回。

0.2.1 将不可变快照保存在扩展的 `MenuBindings`，通过可保留的整数 `NSMenuItem.tag` 关联。不同菜单分配不同 tag，不用新的选择覆盖旧的快照。已增加单元回归测试，并直接操作 Finder 的右键菜单验证已安装版本。

## 可重复执行的验证入口

框架与脚本回归：

```bash
scripts/test.sh
```

本轮为 **19 项通过，0 项失败**，包含重建菜单项不携带 representedObject 时仍可正确解析动作和原始上下文的测试。

已安装扩展的真实右键冒烟检查：

```bash
scripts/finder-smoke.sh /absolute/path/to/test-file SuperRight 复制路径
```

该脚本需要当前终端已有辅助功能权限。它会实际点击菜单、执行所指定动作，并等待与目标路径对应的新执行结果；没有结果或执行失败都会返回非零状态。测试移动、快捷方式、Dock 等动作时应使用自己创建的测试文件，并检查和清理实际副作用。

应用签名使用 `codesign --verify --deep --strict` 验证通过，Finder 扩展注册为 0.2.1。

## 尚不能据此保证的范围

- 未向其他设备发送 LocalSend 文件；这里只确认文件已交给发送界面。
- 未遍历所有 Finder 位置、iCloud Drive、File Provider、外接卷及不同权限目录。
- 未跨其他 macOS 版本或其他电脑验收。

单元测试通过不能代替以上真实集成验收。后续对“可用”的描述必须说明已验证的入口和实际效果。
